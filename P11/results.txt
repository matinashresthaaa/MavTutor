QUESTION: After threading is added, is the order of the prime numbers listed the same or does it vary? Why?
The sequence of prime numbers can be random when using threads. This is because each thread operates on separate parts of the number range and the portions can complete at different times due to their differences in work load. Without specific instructions to merge their results in order, the results can be in a random sequence. This is not the case in a single-thread program where results are predictably organized in a sequence.



QUESTION: Does adding more threads continue to speed up the program? Do more threads ever slow down the program slightly?  Why or why not?
Performance is improved at first when multiple threads are added to the program because there is an increase in parallel work from different CPU cores. That said, there is a limit to the number of threads that can be accommodated. If the number of threads exceeds the number of cores available, there is a decrease in the program’s execution speed as a result of what is referred to as context switching overhead.



QUESTION: Does adding more threads increase the "system load" (sys), or is it constant regardless of the number of threads?  Why?

Increased thread counts increases the load on the system. This is because there is an increase in CPU overhead as thread management, scheduling, and context switching, are handed over to the operating system. A single thread incurs low overhead, but the system overhead continues to increase when more threads are added.
